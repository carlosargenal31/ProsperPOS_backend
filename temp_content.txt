GLOSARIO
API (Application Programming Interface): Conjunto de protocolos, rutinas y herramientas que permiten la comunicación entre diferentes componentes de software. En el contexto del sistema, las APIs facilitan la integración entre módulos de facturación, inventario y comercio electrónico.
Arquitectura Monolítica: Enfoque de desarrollo donde todos los componentes de una aplicación están integrados en una sola unidad desplegable. Apropiada para MiPymes por su simplicidad operacional y menores requerimientos de infraestructura.
Arquitectura de Microservicios: Estilo arquitectónico que estructura una aplicación como una colección de servicios pequeños e independientes que se comunican a través de APIs. Ofrece mayor escalabilidad pero introduce complejidad adicional.
Base de Datos Relacional: Sistema de gestión de bases de datos que organiza la información en tablas relacionadas mediante claves primarias y foráneas, garantizando integridad referencial y consistencia de datos.
Cloud Computing: Modelo de entrega de servicios de computación a través de internet, proporcionando recursos escalables como servidores, almacenamiento y aplicaciones bajo demanda.
Comercio Electrónico (E-commerce): Actividad de compra y venta de productos o servicios a través de internet, incluyendo todas las transacciones comerciales realizadas electrónicamente.
ERP (Enterprise Resource Planning): Sistema integrado de gestión empresarial que centraliza y automatiza procesos de negocio incluyendo finanzas, inventario, ventas y recursos humanos.
Facturación Electrónica: Proceso de emisión, transmisión y recepción de facturas en formato digital, cumpliendo con regulaciones fiscales específicas de cada país.
Framework: Estructura de soporte conceptual y tecnológica que facilita el desarrollo de software proporcionando funcionalidades comunes reutilizables.
Interfaz de Usuario (UI): Medio por el cual el usuario interactúa con un sistema informático, incluyendo elementos visuales como botones, menús y formularios.
Inventario: Registro detallado de bienes y productos disponibles para venta, incluyendo cantidades, ubicaciones y valores monetarios.
JSON (JavaScript Object Notation): Formato ligero de intercambio de datos que es fácil de leer y escribir para humanos y máquinas.
MiPymes: Micro, pequeñas y medianas empresas que constituyen el sector empresarial con limitaciones específicas de personal, volumen de ventas y activos.
MVC (Model-View-Controller): Patrón arquitectónico que separa la lógica de negocio (Modelo), la presentación (Vista) y el control de flujo (Controlador) para mejorar la mantenibilidad del código.
Node.js: Entorno de ejecución de JavaScript del lado del servidor, construido sobre el motor V8 de Chrome, que permite desarrollar aplicaciones web escalables.
Omnicanalidad: Estrategia que integra múltiples canales de venta para proporcionar una experiencia unificada al cliente, independientemente del punto de contacto utilizado.
OMS (Order Management System): Sistema que centraliza y automatiza el procesamiento de pedidos desde su creación hasta la entrega final al cliente.
Pasarela de Pago: Servicio que procesa transacciones con tarjetas de crédito y otros métodos de pago para comercio electrónico, asegurando la transmisión segura de información financiera.
PCI DSS (Payment Card Industry Data Security Standard): Conjunto de estándares de seguridad diseñados para garantizar que todas las empresas que procesan información de tarjetas de crédito mantengan un entorno seguro.
REST (Representational State Transfer): Estilo arquitectónico para servicios web que utiliza métodos HTTP estándar y es stateless, facilitando la escalabilidad y simplicidad.
ROI (Return on Investment): Métrica que evalúa la eficiencia de una inversión calculando la relación entre el beneficio obtenido y el costo de la inversión.
SPA (Single Page Application): Aplicación web que interactúa dinámicamente con el usuario reescribiendo la página actual en lugar de cargar páginas completas desde el servidor.
SSL/TLS (Secure Sockets Layer/Transport Layer Security): Protocolos criptográficos que proporcionan comunicaciones seguras a través de redes informáticas.
Sincronización en Tiempo Real: Proceso que actualiza datos simultáneamente across múltiples sistemas o canales, asegurando consistencia inmediata de información.
Transformación Digital: Proceso integral de adopción de tecnologías digitales para mejorar procesos empresariales, cultura organizacional y experiencias del cliente.
UX (User Experience): Experiencia global que tiene un usuario al interactuar con un producto o servicio, incluyendo aspectos de usabilidad, accesibilidad y satisfacción.
Vue.js: Framework progresivo de JavaScript para construir interfaces de usuario, especialmente efectivo para desarrollo de aplicaciones de página única.
Webhook: Método de comunicación entre aplicaciones que permite enviar datos automáticamente cuando ocurren eventos específicos, facilitando la integración en tiempo real.

PLANTEAMIENTO DEL PROBLEMA
Antecedentes
A nivel global, las micro, pequeñas y medianas empresas (MiPymes) representan más del 90 % del total de empresas y generan entre el 60 % y 70 % del empleo, convirtiéndose en un pilar esencial para la economía . Sin embargo, gran parte de ellas enfrenta un rezago tecnológico significativo, lo que limita su capacidad para competir en un mercado cada vez más digitalizado.
A nivel regional, la tendencia hacia la digitalización, impulsada por la implementación de la factura y el comercio electrónicos, ha demostrado mejoras sustanciales en eficiencia, reducción de costos y aumento de competitividad, en especial en microempresas que anteriormente operaban con procesos manuales .
En el contexto hondureño, las MiPymes generan aproximadamente el 70 % del empleo y contribuyen de forma notable al Producto Interno Bruto (PIB) nacional. A pesar de su importancia, presentan debilidades estructurales en su gestión administrativa y tecnológica  Entre sus principales retos se encuentran la ausencia de sistemas integrados de facturación y control de inventarios, lo que provoca errores frecuentes, pérdida de información, retrasos en procesos y dificultades para cumplir con los requerimientos fiscales.
En ciudades como La Ceiba, muchas empresas familiares mantienen prácticas operativas heredadas que carecen de integración tecnológica, lo que las hace vulnerables ante la competencia de negocios que ya ofrecen canales de venta en línea y procesos automatizados.
Cerámicas y Terrazos Universal constituye un ejemplo representativo de microempresa hondureña que, pese a contar con un catálogo variado de productos, presenta limitaciones derivadas de la gestión manual de ventas y facturación. La falta de herramientas digitales para el control centralizado de inventarios y la comercialización en línea ha reducido su capacidad de respuesta y su alcance comercial.

Definición del Problema
Cerámicas y Terrazos Universal, ubicada en La Ceiba, Honduras, enfrenta deficiencias operativas debido a que su facturación y control de inventario se realizan manualmente y sin integración con una plataforma de comercio electrónico, lo que genera errores, retrasos en la atención al cliente, dificultades para emitir reportes contables y una ausencia de presencia digital que limita su alcance y competitividad en el mercado actual.
Justificación
La digitalización empresarial es un requisito esencial para la permanencia y el fortalecimiento competitivo de las MiPymes, ya que permite optimizar procesos internos, reducir errores, ampliar el alcance de mercado y mejorar la experiencia del cliente  En el caso de Cerámicas y Terrazos Universal, la implementación de un sistema integrado de facturación y comercio electrónico ofrecerá beneficios significativos, al permitir la emisión de comprobantes fiscales conforme a la normativa vigente, el registro en tiempo real de inventarios y la centralización de datos administrativos  Asimismo, la incorporación de un canal de ventas en línea disponible las 24 horas incrementará la cobertura de mercado y atraerá a clientes que actualmente no tienen acceso físico al establecimiento. Esta implementación de sistema también contribuirá a la reducción de costos operativos y a una gestión más eficiente de recursos, elementos clave para fortalecer su posición en un entorno comercial cada vez más competitivo . En este sentido, el proyecto no solo responde a una necesidad operativa inmediata, sino que constituye una estrategia de modernización empresarial orientada al crecimiento sostenible y a la consolidación en el mercado a mediano y largo plazo.


OBJETIVOS
Objetivo General
Desarrollar e implementar en un período de seis meses un sistema integrado de facturación y comercio electrónico para Cerámicas y Terrazos Universal, que permita registrar ventas, emitir facturas y reportes, controlar inventario y ofrecer productos en línea, fortaleciendo la presencia digital de la empresa.
 Objetivos Específicos
Desarrollar un módulo de facturación electrónica que permita emitir comprobantes fiscales cumpliendo con la normativa tributaria vigente en Honduras.
Desarrollar un sistema centralizado de control de inventario que registre en tiempo real las entradas, salidas y existencias de productos.
Diseñar una plataforma de comercio electrónico que permita a los clientes realizar pedidos en línea de manera segura y eficiente.

Base Teórica
Transformación digital y MiPymes
La transformación digital en las MiPymes se ha convertido en un aspecto destacado y fundamental para su competitividad, especialmente en el caso de las economías en desarrollo. Esta tendencia queda corroborada por los resultados de  la tercera Encuesta de Adopción Digital 2023, en la cual el 89% de las Pymes asegura que, durante 2023, espera proceder con su digitalización, con un interés cada vez mayor en el uso de nuevas tecnologías que aumenten su productividad. La citada encuesta también refleja que el 43% de las Pymes emplea herramientas de colaboración digital, el 48% afirma que la implementación de nuevas tecnologías incrementa las ventas, y el 44% sostiene que la transformación digital genera un ahorro considerable. De este modo, los datos obtenidos son una clara muestra de que la transformación digital es más que una simple tendencia; es un proceso que tiene importantes consecuencias en la competitividad y la resiliencia de las MiPymes de la región. El índice de políticas para Pymes de la  destaca que aquellas empresas que adoptan estrategias digitales y acceden a financiamiento verde-digital muestran un mejor desempeño y resiliencia. Según  "la pandemia de COVID-19 aceleró la adopción de pagos digitales y la digitalización en la región, en un proceso que se estaba dando lentamente, y que con la pandemia se dio un gran salto" (p. 12).
Factura electrónica en Latinoamérica
Un aspecto clave del cambio es la factura digital. Latinoamérica ha sido innovadora en esto: usar facturas digitales en lugares como México y Uruguay ha hecho que se recaude más dinero, entre un 3% y 14%, porque hay menos gente que no paga impuestos y es más fácil controlar los impuestos . Según el  en todo el mundo, unos 90 países han implantado o están implantando la facturación electrónica, entre ellos 17 de América Latina y el Caribe. Sus ámbitos de aplicación se han ampliado, como la nómina electrónica, que agiliza la deducción de las cotizaciones a la seguridad social, o los bienes en tránsito. Tipos de Comercio Electrónico e Historia
A lo largo de la historia, el comercio ha recorrido un fascinante camino desde el trueque en sociedades antiguas, una forma de intercambio directo que enfrentaba limitaciones como la coincidencia de necesidades hasta la adopción de monedas en Lidia alrededor del siglo VII a.C., la introducción del papel moneda y los sistemas bancarios, y la llegada de las transacciones digitales en el siglo XX para dar paso finalmente al comercio electrónico en el siglo XXI; esta evolución no solo refleja cambios tecnológicos sino también culturales en nuestra forma de intercambiar valor  .
 En la actualidad, el e-commerce se ha diversificado en múltiples modelos de negocio, incluyendo los tradicionales como Business to Consumer (B2C), Business-to-Business (B2B), Consumer to Consumer (C2C) y Consumer to Business (C2B), así como también aquellos enfocados en relaciones con el sector público como Business to Administration (B2A) y Consumer to Administration (C2A) todos descritos en estudios recientes sobre tendencias de 2025, además de modelos emergentes como D2C (Direct to Consumer), que elimina intermediarios, Q-commerce, centrado en entregas ultrarrápidas, y social commerce, que aprovecha las redes sociales para ventas integradas y espontáneas. Esta trayectoria histórica y esta nueva pluralidad de modalidades evidencian que el comercio ha pasado de intercambios locales y físicos a ser un ecosistema global, instantáneo, eficiente y altamente especializado, capaz de responder a las exigencias de consumo y conectividad del siglo XXI.

Experiencia de usuario (UX), pagos en línea y seguridad
La forma en que el usuario vive el sitio (UX) es clave para que compre en sitios web. Las investigaciones del  revelan que el 70% de los usuarios de e-commerce abandonan su compra después de agregar artículos al carrito, y que el diseño y flujo del checkout es frecuentemente la única causa de que los usuarios abandonen durante el proceso de checkout. Los problemas mayores identificados incluyen el 50% de sitios que no hacen prominente la opción de "checkout como invitado", el 65% que tienen requisitos de contraseña excesivamente complejos, y el 74% que no marcan claramente cuáles campos son obligatorios y cuáles opcionales. Estos obstáculos en el proceso de compra hacen que muchos no terminen la transacción. Por esto, es fundamental que las páginas sean más fáciles de entender para todos los usuarios, y que se sigan las reglas de seguridad internacionales para cuidar los datos bancarios de los clientes y que se sientan seguros al pagar online.
Patrón Modelo-Vista-Controlador (MVC)
La arquitectura Modelo-Vista-Controlador constituye uno de los pilares fundamentales más sólidos para el desarrollo de aplicaciones web escalables y de alta eficiencia. Según la investigación publicada por , este patrón arquitectónico permite una separación clara entre la lógica de presentación y los procesos de negocio, facilitando considerablemente las tareas de mantenimiento y evolución del sistema. En el contexto de plataformas integradas que combinan facturación electrónica y comercio digital, esta división arquitectónica resulta esencial para gestionar la complejidad inherente a los múltiples módulos funcionales que requieren interoperabilidad y coordinación de procesos empresariales en tiempo real.
El modelo representa la capa de datos y lógica de negocio, encargándose de la gestión de inventarios, procesamiento de facturas, cálculos fiscales y validaciones comerciales. La vista se responsabiliza de la presentación de información tanto para usuarios finales en la tienda en línea como para administradores en el panel de facturación. El controlador actúa como intermediario, procesando las solicitudes del usuario y coordinando las respuestas apropiadas entre modelo y vista

Arquitectura de Microservicios versus Arquitectura Monolítica
Para sistemas que integran facturación y comercio electrónico, la elección arquitectónica impacta directamente en la escalabilidad, mantenimiento y capacidad de evolución del sistema. Según  una arquitectura monolítica ofrece ventajas significativas para MiPymes por su simplicidad de despliegue y menor complejidad operacional inicial.
 establece que el compromiso principal entre estas arquitecturas es simplicidad versus flexibilidad. Para equipos pequeños o productos en etapa temprana, los monolitos son frecuentemente más rápidos de construir, más fáciles de probar y más simples de gestionar. Los microservicios solo proporcionan beneficios cuando el sistema es lo suficientemente grande para justificar la complejidad adicional.
En el contexto específico de este proyecto,  señala que las aplicaciones monolíticas pueden presentar dificultades para mantener el ritmo de industrias en rápido movimiento, ya que pueden ser inflexibles y difíciles de escalar. Sin embargo, para empresas como Cerámicas y Terrazos Universal, un enfoque monolítico bien estructurado con límites modulares claros permite futuras migraciones hacia microservicios conforme crezcan las necesidades del negocio.
 introduce el concepto de "monolito modular" como una alternativa seria a los microservicios en 2025, combinando la simplicidad de los monolitos con las buenas prácticas de la arquitectura de microservicios. Esta aplicación se despliega como un sistema único, pero está claramente dividida en módulos independientes con responsabilidades bien definidas.

Integración de Sistemas de Facturación y Comercio Electrónico
Sincronización de Inventarios en Tiempo Real
La sincronización de inventarios en tiempo real constituye un elemento crítico para sistemas integrados de facturación y comercio electrónico. Según , la integración de capacidades permite que las actualizaciones de inventario se procesen simultáneamente a través del sitio web, Amazon y socios minoristas. Esta sincronización multicanal previene el pecado cardinal del comercio electrónico: vender productos que no están disponibles.
 confirma que la sincronización de datos en tiempo real garantiza que cada plataforma (sitio web, CRM, ERP, etc.) refleje la información más actualizada. Los clientes se benefician al ver la disponibilidad de productos en tiempo real, haciendo que su experiencia de compra sea más fluida y confiable. Sin integración adecuada, las empresas corren el riesgo de sobreventa y agotamiento de existencias.
Para sistemas como el propuesto para Cerámicas y Terrazos Universal, esta sincronización debe manejar el flujo bidireccional de datos entre módulos de inventario y comercio electrónico.  señala que las plataformas automatizadas sincronizan los costos de inventario y ventas con sistemas contables, manteniendo registros financieros e inventario precisos sin intervención manual.
Flujos de Datos entre Módulos
Los flujos de datos efectivos entre módulos de facturación, inventario y comercio electrónico requieren arquitecturas que soporten operaciones en tiempo real.  establece que cuando un cliente realiza un pedido, el sistema debe actualizar automáticamente el inventario, crear etiquetas de envío, ajustar las finanzas y actualizar perfiles de clientes a través de todos los canales de venta.
 describe el flujo típico: cuando un cliente realiza un pedido, el sistema de gestión de pedidos (OMS) captura los detalles y verifica automáticamente la disponibilidad de inventario. Luego inicia el proceso de cumplimiento, incluyendo picking, empaque y envío. El OMS automatiza los niveles de inventario en tiempo real y genera etiquetas de envío.
La integración requiere que los datos fluyan de manera coherente entre diferentes sistemas empresariales.  confirma que los niveles de inventario se sincronizan entre los dos sistemas para garantizar que los niveles de stock sean consistentes. Cuando se realizan nuevos pedidos en la plataforma de comercio electrónico, el ERP genera automáticamente órdenes de compra.
Gestión de Estados de Pedidos
La gestión efectiva de estados de pedidos es fundamental para mantener la integridad de datos y la experiencia del cliente.  define que un OMS rastrea los niveles de inventario por canal, automatiza el proceso de cumplimiento de pedidos, maneja la logística inversa, gestiona información de clientes y fusiona datos de pedidos y financieros.
 identifica que muchas soluciones tradicionales de gestión de pedidos carecen de capacidades de automatización para entrada de pedidos, cumplimiento y servicio al cliente, lo que resulta en procesos que consumen tiempo y son propensos a errores humanos. El enrutamiento de pedidos impulsado por IA puede analizar factores como niveles de stock, ubicaciones geográficas y ventanas de entrega para determinar la estrategia de cumplimiento más eficiente.
 enfatiza que la integración de APIs fomenta un ecosistema unificado al conectar el Sistema de Gestión de Pedidos con otros sistemas empresariales cruciales como CRMs, software de contabilidad o plataformas de marketing. Esto permite un flujo de datos sin interrupciones, mejorando la eficiencia operacional general.
Para el sistema propuesto, los estados de pedidos deben incluir: pedido recibido, verificación de inventario, procesamiento de pago, preparación para envío, enviado, entregado y, en caso necesario, devolución procesada. Cada transición de estado debe actualizarse automáticamente en todos los módulos conectados, manteniendo consistencia de datos y trazabilidad completa.

Desde el año 2017, el país de Honduras se había establecido y ha sido creciendo con el pacto No. 481-2017 , que fue el que daba regulaciones para la expedición de las papelerías de impuestos, la facturación digital, el registro de las imprentas y los reglamentos de control tributario, y después dio tres cambios principales que fueron el Acuerdo No. 609-2017 , No. 725-2018  y el No. 817-2018  en los cuales se realizaron cambios en las definiciones, el formato de los documentos, los derechos de los obligados tributarios y el uso de la numeración fiscal. 
Por el momento, el texto unido es el que contiene todos los cambios que han sucedido en un solo papel actualizado y por lo tanto mejor para su búsqueda 
En otro orden de cosas, el pacto No. 231-2020, de la, fue el que salió en el año 2020 y que permitió por un tiempo (en ese año) la impresión de las papelerías de impuestos a determinados obligados tributarios con problemas extraños.
Ley sobre Firmas Electrónicas
Ley sobre Firmas Electrónicas (Decreto No. 149-2013)  es la fundamental para validar la integridad y autenticidad de documentos electrónicos, incluyendo facturas. Esta normativa establece:
La validez jurídica de la firma electrónica, equiparándola a la manuscrita si cumple los requisitos legales.
La definición de conceptos clave como firma electrónica avanzada y certificado digital.
Normas de neutralidad tecnológica, responsabilidad de entidades certificadoras y manejo de certificaciones electrónicas.
A pesar de su antigüedad, sigue vigente y es pieza esencial en el marco legal de facturación electrónica en Honduras.

METODOLOGÍA
Métodos
Para el desarrollo del sistema de facturación integrado con plataforma de comercio electrónico para Cerámicas y Terrazos Universal, se adoptó un enfoque metodológico mixto que combina elementos cualitativos y cuantitativos:
Definición de Enfoque Metodológico
Un enfoque metodológico se define como "la perspectiva general que adopta el investigador para abordar el problema de investigación, determinando la estrategia de indagación y los métodos específicos de recolección y análisis de datos" 
Método Cualitativo
El enfoque cualitativo se caracteriza por ser "un procedimiento metodológico que utiliza palabras, textos, discursos, dibujos, gráficos e imágenes para comprender la vida social del sujeto a través de los significados desarrollados por éste" . Este enfoque utiliza la recolección de datos sin medición numérica predominante, busca comprender el contexto y los significados profundos, se fundamenta en un proceso inductivo y flexible, permite adaptabilidad en el diseño de investigación y se orienta hacia la descripción profunda del fenómeno. Se implementó para comprender las necesidades específicas del negocio, los procesos actuales de facturación y las expectativas de los usuarios mediante cuatro técnicas principales que se detallan en la sección 5.3.1.
Método Cuantitativo
El enfoque cuantitativo "se caracteriza por la medición de fenómenos utilizando la recolección de datos para probar hipótesis y teorías a través de análisis estadísticos. Su proceso de realización es deductivo, secuencial y busca tener mayor objetividad" . Se caracteriza por la medición de variables y análisis estadístico riguroso, proceso deductivo y secuencial estructurado, objetividad en la recolección y análisis de datos, generalización y validación de resultados, y uso de técnicas estadísticas para la interpretación. Se aplicó para medir la efectividad del sistema desarrollado y validar mejoras en eficiencia operacional mediante técnicas específicas de medición y análisis que se detallan en la sección 5.3.1.
Justificación del Enfoque Mixto
Según , "la investigación mixta se refiere a la combinación de métodos cuantitativos y cualitativos en un solo estudio para entender un problema de investigación complejo". Esta integración metodológica permite complementariedad, completitud, confirmación, expansión y triangulación de los resultados obtenidos. Para este proyecto se adoptó un diseño mixto secuencial explicativo, donde "primero se recopilan y analizan datos cuantitativos. Sobre la base de ellos, se organiza luego la recopilación y análisis de los datos cualitativos para obtener una comprensión más profunda del fenómeno"

Diseño GUI
Una interfaz gráfica de usuario (GUI) es la presentación de la interacción, a nivel visual, entre un dispositivo y su usuario. Se trata de un elemento imprescindible dentro del mundo del diseño y del desarrollo que incluye botones, menús, ventanas y otros elementos visuales que permiten a los usuarios interactuar con sistemas informáticos de manera intuitiva. 
Diseño de Pantallas
Pantalla de Inicio de Sesión

Ilustración ‎5.6.1.1 Pantalla de Inicio de Sesión
La pantalla de inicio de sesión es el punto de acceso principal al sistema ProsperPOS. Presenta el logotipo de la aplicación en la parte superior, seguido del título "Iniciar Sesión" con su respectivo subtítulo explicativo. El formulario de acceso incluye dos campos principales: Email o Usuario donde se ingresa el correo electrónico o nombre de usuario, y Contraseña con visualización oculta mediante asteriscos. Debajo de estos campos se encuentra la opción "Recordarme" para mantener la sesión activa, junto al enlace "¿Olvidaste tu contraseña?" que permite la recuperación de credenciales mediante verificación SMTP en la base de datos. El botón naranja "Iniciar Sesión" completa el formulario y da acceso al panel administrativo del sistema.
Pantalla de Clientes

Ilustración ‎5.6.1.2 Lista de Clientes
La pantalla principal de clientes muestra una tabla completa con todos los clientes registrados en el sistema. Esta tabla incluye columnas para Código (identificador único del cliente), Nombre (razón social o nombre del cliente), Estado (badge verde para Activo o rojo para Inactivo) y Acciones. En la parte superior de la pantalla se encuentran los botones para exportar la información en formato PDF y Excel (botón verde), así como los controles para recargar la página y minimizar el encabezado. A la derecha se ubica el botón naranja "Agregar Nuevo Cliente" que despliega el modal de registro. Los clientes registrados pueden ser seleccionados durante el proceso de facturación y son utilizados para generar reportes de ventas, y estados de cuenta.

Ilustración ‎5.6.1.3 Agregar Cliente
Al presionar el botón "Agregar Nuevo Cliente", se despliega un modal con el formulario de registro. Este incluye los campos Código (generado automáticamente), Nombre completo del cliente, Nombre Comercial y Código Tipo Precio para asignar lista de precios específica. También solicita el Documento de Identificación (RTN/DNI) de 14 dígitos, Teléfono de contacto, Email y Fecha de Inicio para registrar desde cuándo es cliente. El campo Dirección permite ingresar la ubicación completa del cliente, seguido de Descuento (%) para aplicar descuentos automáticos y Persona de Contacto. El toggle "Activo" permite definir si el cliente está habilitado en el sistema. Los botones Cancelar y Guardar completan la acción de registro.

Ilustración ‎5.6.1.4 Visualizar Cliente
La acción de visualización se activa mediante el icono de ojo en la columna de Acciones. Este modal muestra todos los datos del cliente en modo de solo lectura, sin permitir modificaciones. Se presenta la misma estructura del formulario de registro pero con los campos deshabilitados para edición. Esta función es útil para consultar rápidamente la información completa de un cliente sin riesgo de modificar accidentalmente sus datos. El modal incluye únicamente los botones para Cerrar (X) y el botón "Cerrar" en la parte inferior.

Ilustración ‎5.6.1.5 Editar Cliente
El modal de edición se accede mediante el icono de lápiz en las acciones de cada cliente. Presenta exactamente los mismos campos que el formulario de agregar cliente, pero precargados con la información actual del registro seleccionado. Todos los campos son editables, permitiendo actualizar cualquier dato del cliente como nombre, documento de identificación, contacto, dirección, descuentos aplicables o estado. El botón "Guardar Cambios" (color naranja) confirma las modificaciones realizadas, mientras que el botón Cancelar descarta los cambios y cierra el modal sin afectar la información original.

Ilustración ‎5.6.1.6 Eliminar Cliente
Al hacer clic en el icono de basurero, se muestra un modal de confirmación para eliminar el cliente. Este diálogo presenta un icono de advertencia en rojo junto al mensaje "Eliminar Cliente" y la pregunta de confirmación "¿Estás seguro de que deseas eliminar este cliente?". El modal ofrece dos opciones: el botón "Cancelar" (gris oscuro) que aborta la operación y cierra el modal, y el botón "Sí, Eliminar" (rojo) que ejecuta la eliminación definitiva del registro. Esta acción debe realizarse con precaución ya que la eliminación de un cliente puede afectar el historial de ventas y reportes asociados.
Pantalla De Proveedores

Ilustración ‎5.6.1.7 Lista de Proveedores
La pantalla de administración de proveedores presenta una tabla detallada con todos los proveedores registrados. Identificación con el formato de RTN hondureño de 14 dígitos, Tipo Beneficiario mostrado en badge azul (Jurídica Domiciliada, Natural Residente, etc.), Estado (Activo/Inactivo) y Acciones con los iconos de visualizar, editar y eliminar. La barra superior contiene las opciones de exportación a PDF y Excel, actualización de datos y el botón principal "Agregar Proveedor" en color naranja. Los proveedores son fundamentales para el módulo de compras, permitiendo registrar órdenes de compra, controlar inventario entrante y gestionar cuentas por pagar.

Ilustración ‎5.6.1.8 Agregar Proveedor
El formulario de nuevo proveedor se despliega en un modal con los campos esenciales para el registro. Incluye Nombre del proveedor (razón social), Tipo de Proveedor con opciones como Nacional o Internacional (opcional), y Doc. Identificación para ingresar el RTN o número de identificación fiscal. El campo Tipo Beneficiario es un selector desplegable con opciones precargadas como Jurídica Domiciliada, Natural Residente, etc. El toggle "Usa Crédito" permite habilitar líneas de crédito con el proveedor, mientras que el toggle "Activo" define si está habilitado para operaciones. Los botones Cancelar y Guardar completan el proceso de registro. 

Ilustración ‎5.6.1.9 Visualizar Proveedor
La visualización de proveedores muestra todos los campos en modo de solo lectura. No permite ninguna modificación de datos y sirve únicamente para consultar rápidamente la información completa de un proveedor específico. Esta función es especialmente útil cuando múltiples usuarios necesitan consultar información sin riesgo de alterarla accidentalmente.

Ilustración ‎5.6.1.10 Editar Proveedor

La edición de proveedores mantiene la misma estructura del formulario de agregar, pero con los datos actuales del proveedor seleccionado. Permite modificar el nombre, tipo de proveedor, documento de identificación, tipo de beneficiario y los estados de uso de crédito y activo. Esta función es útil cuando cambian las condiciones comerciales con un proveedor, se actualiza su información fiscal o se necesita desactivar temporalmente un proveedor sin eliminarlo del sistema. El botón "Guardar Cambios" confirma las modificaciones mientras que Cancelar descarta los cambios.

Ilustración ‎5.6.1.11 Eliminar Proveedor
El modal de eliminación presenta el mensaje de confirmación "¿Estás seguro? ¿Deseas eliminar este proveedor?" con el icono de advertencia en rojo. Ofrece las opciones de Cancelar para abortar la operación o "Sí, Eliminar" para confirmar. Es importante considerar que eliminar un proveedor puede afectar el historial de compras, órdenes pendientes y reportes asociados, por lo que se recomienda verificar estas dependencias antes de proceder.

Ilustración ‎5.6.1.12 Lista de Sucursales
La pantalla de sucursales administra las diferentes tiendas o puntos de venta de la empresa. La tabla muestra columnas para ID, Nombre de la sucursal, Ciudad donde se encuentra ubicada, Departamento, Gerente responsable, Teléfono de contacto, Estado (Activo/Inactivo) y Acciones. En la parte superior se encuentran los botones de exportación a PDF y Excel, actualización de página y el botón naranja "Agregar Nueva Sucursal". Las sucursales son esenciales para el control de inventario multi-tienda, asignación de personal, generación de reportes por ubicación y gestión de ventas descentralizadas. Cada sucursal puede tener su propio stock, personal y configuración de precios.

Ilustración ‎5.6.1.13 Agregar Sucursal
El modal de nueva sucursal incluye el campo Nombre para identificar la tienda o punto de venta, Ciudad con selector desplegable de ciudades registradas en el sistema, y Dirección para especificar la ubicación exacta completa. El campo Teléfono almacena el número de contacto principal de la sucursal, Correo Electrónico para comunicaciones oficiales, y Gerente con el nombre del responsable de la sucursal. El toggle Estado permite activar o desactivar la sucursal en el sistema. Los botones Cancelar y Guardar completan el registro.

Ilustración ‎5.6.1.14 Visualizar Sucursal
La acción de visualización se activa mediante el icono de ojo en la columna de Acciones. Este modal muestra todos los datos de la sucursal en modo de solo lectura, sin permitir modificaciones.

Ilustración ‎5.6.1.15 Editar Sucursal
La edición de sucursales permite modificar todos los campos del registro original. Resulta útil cuando se cambia de gerente, se actualiza información de contacto, se modifica la dirección física o cuando una sucursal necesita ser desactivada temporalmente sin eliminarla del sistema. Todos los datos históricos y transacciones vinculadas a la sucursal se mantienen intactos. El botón "Guardar Cambios" confirma las modificaciones realizadas.

Ilustración ‎5.6.1.16 Eliminar Sucursal
El modal de confirmación pregunta "¿Estás seguro? ¿Deseas eliminar esta sucursal?" con el icono de advertencia. La eliminación de una sucursal es una operación crítica que debe evaluarse cuidadosamente ya que puede afectar inventarios, ventas históricas, asignación de personal y reportes. Se recomienda verificar que no existan transacciones pendientes o inventario activo antes de proceder con la eliminación.

Ilustración ‎5.6.1.17 Lista de Bodegas

Las bodegas son fundamentales para el control de inventario, gestión de entradas y salidas de mercancía, traslados entre ubicaciones y reportes de stock por almacén. Cada bodega puede estar asociada a una o varias sucursales, permitiendo un control preciso de la distribución de productos. La barra superior incluye exportación a PDF/Excel y el botón "Agregar Nueva Bodega".

Ilustración ‎5.6.1.18 Agregar Bodega

Ilustración ‎5.6.1.19 Visualizar Bodega
El modal de visualización de bodegas se accede mediante el icono de ojo. Muestra en modo de solo lectura el nombre de la bodega, encargado responsable, ubicación física del almacén y estado actual.

Ilustración ‎5.6.1.20 Editar Bodega
La edición permite actualizar el nombre de la bodega, cambiar el encargado responsable, modificar la ubicación física o cambiar el estado activo/inactivo. Esta función es útil cuando se reorganiza la estructura de almacenamiento, se cambia personal o se actualiza información de ubicación. Todas las transacciones y movimientos de inventario previos se mantienen vinculados a la bodega.

Ilustración ‎5.6.1.21 Eliminar Bodega

Es crucial verificar que la bodega no tenga inventario activo, transferencias pendientes o movimientos sin cerrar antes de eliminarla. La eliminación puede afectar reportes históricos y trazabilidad de productos.

Pantalla de Vehículos

Ilustración ‎5.6.1.22 Lista de Vehículos
La gestión de vehículos registra la flota de transporte de la empresa para entregas y distribución. Los vehículos registrados pueden asignarse a rutas de entrega, empleados conductores, y son útiles para control de gastos de combustible, mantenimiento y logística. Esta información es valiosa para reportes de distribución y control de activos de la empresa.

Ilustración ‎5.6.1.23 Agregar Vehículo
El formulario de nuevo vehículo incluye Placa con el número de matrícula oficial, Marca del fabricante (ej: Toyota, Honda, Hino), Modelo específico del vehículo (ej: Hilux 2020), y Color para identificación visual. Ilustración ‎5.6.1.24 Visualizar Vehículo
La visualización de vehículos muestra todos los detalles en modo de consulta únicamente. El modal presenta placa de identificación, marca, modelo, color y estado de disponibilidad.

Ilustración ‎5.6.1.25 Editar Vehículo
La edición permite actualizar cualquier información del vehículo como placa (en caso de renovación), marca y modelo si hubo error en el registro inicial, color si fue repintado, y especialmente el estado para marcarlo como inactivo durante períodos de mantenimiento o cuando sale de la flota.

Ilustración ‎5.6.1.26 Eliminar Vehículo
La confirmación de eliminación pregunta "¿Estás seguro? ¿Deseas eliminar este vehículo?". Antes de eliminar se debe verificar que no existan asignaciones activas de entregas, rutas pendientes o registros de mantenimiento sin cerrar vinculados al vehículo.

Ilustración ‎5.6.1.31 Eliminar País

RESULTADOS Y ANÁLISIS
Resultados de Instrumentos de Recolección de Datos
La entrevista realizada al gerente Daniel Bonilla (ver anexo 1) reveló que la empresa opera desde hace 22 años con 6 empleados, procesando entre 150 y 300 facturas mensuales dependiendo de la temporada de construcción. El sistema de facturación actual, implementado hace año y medio, presenta limitaciones significativas al no integrarse con el inventario, requiriendo doble trabajo y verificación manual constante. El control de inventario se maneja mediante hojas físicas de papel, donde los vendedores deben anotar manualmente las ventas después de facturar en el sistema, generando constantemente desfases entre el sistema de facturas y el stock real en bodega.
La sesión con el personal operativo (ver anexo 2) identificó que el mayor desafío para ventas es la realización de cálculos manuales de impuestos y descuentos, con temor constante a cometer errores. El personal de bodega manifestó la falta de información en tiempo real sobre ventas, generando situaciones donde clientes buscan productos que según registros existen, pero físicamente no están disponibles. Todo el personal demostró familiaridad básica con tecnología y disposición para aprender sistemas nuevos si son intuitivos.
Durante las 40 horas de observación distribuidas en dos semanas (ver anexo 3) se documentó que el tiempo promedio por venta es de 8 minutos, detectándose errores de cálculo de impuestos, inconsistencias entre inventario registrado y físico, y omisiones en la actualización manual de hojas de inventario. El proceso de entrada de mercadería nueva requiere 70 minutos, observándose conteo manual duplicado por desconfianza e información no disponible inmediatamente para vendedores. La preparación del reporte mensual para SAR consume 5.25 horas, identificándose facturas con errores de cálculo, facturas duplicadas e información inconsistente entre diferentes fuentes.

La encuesta digital aplicada a 30 clientes frecuentes (ver anexo 4) reveló que el 50% tiene entre 31 y 45 años, el 60% realiza compras mensuales, y solo el 46.7% califica el proceso actual como bueno o excelente. Los principales puntos de insatisfacción son lentitud en el proceso de facturación (46.7%), falta de productos mostrados o disponibles (26.7%), y errores en las facturas (16.7%). Un contundente 86.7% desea ver productos en línea antes de visitar la tienda, mientras que el 86.7% está interesado en hacer pedidos por internet para recoger en tienda. Para compras en línea, el 93.9% prefiere tarjeta de crédito o débito, 50% transferencia bancaria, y 40% efectivo. Estos resultados validan la necesidad de integrar múltiples métodos de pago priorizando las pasarelas electrónicas.
La lista de verificación técnica (ver anexo 5) documentó que la empresa cuenta con 1 computadora de escritorio con Windows 10, 5 smartphones Android, impresoras térmicas y de documentos, y router WiFi con conexión de 10 Mbps. La infraestructura eléctrica es estable con planta eléctrica de respaldo. El administrador y vendedores tienen nivel intermedio de competencias tecnológicas, mientras que el personal de bodega y motorista tienen nivel básico.
Análisis Integral del Sistema Desarrollado
El sistema fue desarrollado utilizando arquitectura monolítica modular con separación clara entre componentes. La capa de presentación fue desarrollada con Vue.js 3.4 utilizando Composition API y Tailwind CSS, implementando diseño responsive. La capa de lógica de negocio se construyó con Node.js 20 LTS y Express.js implementando patrón MVC. La capa de datos utiliza MySQL 8.0 garantizando integridad referencial mediante claves y procedimientos almacenados. Se implementaron múltiples capas de seguridad incluyendo autenticación basada en JWT, control de acceso basado en roles, y tokenización de información de tarjetas. El sistema incluye registro completo de transacciones con timestamps y backup automático diario con retención de 30 días. El sistema fue diseñado considerando crecimiento futuro mediante índices optimizados, paginación de resultados, cacheo de catálogo, arquitectura modular que permite agregar nuevos módulos, capacidad de escalamiento horizontal, y dashboard administrativo con métricas en tiempo real.

Conclusiones
Objetivo Específico 1: Módulo de Facturación Electrónica
El desarrollo del módulo de facturación electrónica permitió construir un sistema capaz de emitir comprobantes fiscales cumpliendo con los lineamientos establecidos por el SAR, integrando validaciones automáticas, cálculos precisos y una estructura de datos completa que centraliza la información requerida por la normativa. La automatización del proceso redujo significativamente el tiempo de facturación y eliminó errores comunes asociados al manejo manual, lo cual mejora la eficiencia interna y la atención al cliente. Además, el diseño del módulo permitió que la información se almacene de forma ordenada y segura, facilitando la generación de reportes fiscales y financieros y la trazabilidad de cada transacción. Este avance representa un paso importante para la modernización operativa de la empresa, ya que incorpora buenas prácticas tecnológicas, unifica criterios de registro y establece bases sólidas para futuras integraciones legales o administrativas.
Objetivo Específico 2: Sistema de Control de Inventario
El sistema de control de inventario demostró ser una herramienta esencial para resolver los problemas originados por el manejo manual de existencias, ya que permitió registrar en tiempo real los movimientos de productos y mejorar la precisión del stock disponible. La integración con el módulo de facturación garantiza que cada venta actualice el inventario automáticamente, eliminando desfases que antes generaban errores y decisiones equivocadas. Las pruebas evidenciaron una reducción considerable en el tiempo necesario para ingresar mercancía, además de proporcionar indicadores útiles como valor total del inventario, productos críticos y rotación por categoría. Esta plataforma centralizada fortaleció la capacidad operativa de la empresa al ofrecer visibilidad clara y ordenada del inventario, reduciendo pérdidas, mejorando procesos de compra y permitiendo una administración más eficiente de los recursos disponibles.
Objetivo Específico 3: Plataforma de Comercio Electrónico
La plataforma desarrollada permitió crear un espacio digital donde los clientes pueden visualizar el catálogo completo de productos y realizar solicitudes de pedidos o cotizaciones de manera rápida y estructurada directamente en línea. Este enfoque facilita que el cliente envíe sus requerimientos al vendedor, quien podrá revisar existencias, aplicar precios y responder con una cotización formal, manteniendo el control comercial dentro del proceso interno de la empresa. La integración con el inventario asegura que la información enviada al cliente esté siempre actualizada, evitando ofrecer productos sin disponibilidad. Además, el diseño intuitivo, la presentación clara de los productos y la posibilidad de solicitar una cotización desde cualquier dispositivo fortalecen la accesibilidad del servicio y amplían el alcance comercial de la empresa, permitiendo atender más clientes sin depender exclusivamente de la interacción presencial o telefónica.

RECOMENDACIONES
Objetivo Específico 1: Módulo de Facturación Electrónica
Se recomienda fortalecer el módulo incorporando funciones avanzadas como el envío automático de facturas al cliente por correo electrónico, la integración con firma electrónica para mejorar la validez legal de los comprobantes y la generación de archivos XML compatibles con los formatos utilizados por el SAR. También sería conveniente implementar alertas para errores fiscales frecuentes, plantillas configurables para diferentes tipos de documentos y un módulo de auditoría interna que registre cambios o modificaciones realizadas por los usuarios. Estas mejoras permitirán consolidar el sistema como una herramienta más completa, segura y preparada para futuras actualizaciones normativas.
Objetivo Específico 2: Sistema de Control de Inventario
Se recomienda ampliar las funcionalidades del sistema mediante la incorporación de un módulo de pronóstico de demanda basado en el historial de ventas, lo que permitirá anticipar necesidades de reposición y evitar quiebres de stock. También se sugiere integrar el sistema con proveedores para generar órdenes de compra automáticas cuando un producto alcance su nivel mínimo, así como habilitar un proceso de inventario físico periódico para comparar existencias reales con los registros del sistema. Finalmente, se recomienda desarrollar reportes más avanzados que permitan identificar tendencias de consumo y márgenes de rentabilidad para optimizar las decisiones de compra.
Objetivo Específico 3: Plataforma de Comercio Electrónico
Se recomienda incorporar un módulo de seguimiento de solicitudes donde cada cliente pueda ver el estado de su pedido o cotización, incluyendo actualizaciones del vendedor en tiempo real. También sería útil habilitar notificaciones por correo o mensaje cuando la cotización sea enviada o modificada, fortaleciendo la comunicación y reduciendo tiempos de respuesta. Además, se sugiere implementar un historial de solicitudes previas, la posibilidad de adjuntar detalles adicionales y un espacio de comentarios entre cliente y vendedor para aclaraciones rápidas. Finalmente, se recomienda dejar preparada la plataforma para habilitar compras en línea en el futuro, de manera que, cuando la empresa lo decida, pueda activar esta función sin necesidad de realizar cambios estructurales mayores, garantizando una transición ordenada y controlada hacia un modelo de venta digital completa.
