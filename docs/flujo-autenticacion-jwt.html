🔐 Flujo de Autenticación JWT

Sistema de Autenticación y Autorización - ProsperPOS

1
Inicio de Sesión (Login)
1
Cliente envía credenciales
El usuario ingresa email y contraseña desde el formulario de login
POST /api/auth/login
{ email, password }
2
Validación de credenciales
El servidor verifica el usuario en la base de datos y compara el hash de la contraseña con bcrypt
bcrypt.compare(password, hash)
3
Verificación de permisos
Se obtienen los roles y permisos del usuario desde la base de datos (RBAC)
getUserWithPermissions(userId)
4
Generación de tokens
Se generan Access Token (15 min) y Refresh Token (7 días) con JWT
jwt.sign(payload, SECRET)

🎫 Access Token

Token de corta duración usado para acceder a recursos protegidos

⏱️ Duración: 15 minutos

Payload: { userId, email, roles, permissions }

🔄 Refresh Token

Token de larga duración usado para obtener nuevos Access Tokens

⏱️ Duración: 7 días

Almacenado en: Base de datos (tabla refresh_tokens)

⬇️
2
Acceso a Recursos Protegidos

👤 Cliente

Envía petición con Access Token en header

Authorization:
Bearer <token>
→

🛡️ Middleware

verifyToken() valida el JWT y extrae el payload

jwt.verify(token, SECRET)
→

🔑 checkPermission()

Verifica que el usuario tenga el permiso requerido

hasPermission(resource, action)
→

✅ Recurso

El controlador procesa la petición y retorna la respuesta

⬇️
3
Renovación de Token (Access Token expirado)
1
Token expirado
El Access Token expira después de 15 minutos. El servidor retorna error 401
Error: Token expired
2
Cliente solicita renovación
El cliente envía el Refresh Token al endpoint de renovación
POST /api/auth/refresh
{ refreshToken }
3
Validación del Refresh Token
Se verifica que el Refresh Token exista en la base de datos y no haya expirado
findRefreshToken(token)
4
Nuevo Access Token
Se genera un nuevo Access Token con 15 minutos de validez
jwt.sign(payload, SECRET, 15m)
⬇️
4
Cierre de Sesión (Logout)
1
Cliente solicita logout
El usuario cierra sesión desde la aplicación
POST /api/auth/logout
2
Eliminación de Refresh Token
Se elimina el Refresh Token de la base de datos
DELETE FROM refresh_tokens
3
Cliente limpia tokens
El cliente elimina ambos tokens del almacenamiento local
localStorage.clear()
🔒
Características de Seguridad

🔐 Encriptación

  • Contraseñas hasheadas con bcrypt (salt rounds: 10)
  • Tokens firmados con secreto JWT
  • HTTPS en producción

🛡️ Protección contra ataques

  • Helmet.js (headers de seguridad)
  • CORS configurado
  • Rate limiting (express-rate-limit)
  • XSS protection

✅ Control de acceso (RBAC)

  • Roles: Administrador, Vendedor, Gerente, etc.
  • Permisos granulares por recurso
  • Middleware checkPermission()
  • Validación en cada endpoint

🔄 Gestión de sesiones

  • Refresh tokens en base de datos
  • Expiración automática
  • Revocación manual (logout)
  • Un refresh token por sesión

📝 Auditoría

  • Logs con Winston
  • Registro de intentos de login
  • Tracking de cambios críticos
  • Monitoreo de tokens expirados

⚙️ Configuración

  • Variables de entorno (.env)
  • Secretos no versionados
  • Diferentes configs por ambiente
  • Validación con express-validator
