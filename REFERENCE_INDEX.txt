=== DATABASE SCHEMA ===

CREATE TABLE beneficiary_types (
  id INT AUTO_INCREMENT PRIMARY KEY,
  codigo VARCHAR(10) UNIQUE,
  nombre VARCHAR(100),
  is_active TINYINT(1) DEFAULT 1,
  created_by INT, updated_by INT, deleted_by INT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP AUTO UPDATE,
  deleted_at TIMESTAMP NULL,
  
  FOREIGN KEY (created_by) REFERENCES users(id),
  FOREIGN KEY (updated_by) REFERENCES users(id),
  FOREIGN KEY (deleted_by) REFERENCES users(id)
);

=== API ENDPOINTS ===

GET /api/v1/beneficiary-types
  Returns all non-deleted records
  Query: SELECT * WHERE deleted_at IS NULL

POST /api/v1/beneficiary-types
  Create new record
  Body: {nombre, is_active}
  Validations: required, unique

PUT /api/v1/beneficiary-types/:id
  Update record
  Body: {nombre, is_active}
  Auto sets: updated_by, updated_at

DELETE /api/v1/beneficiary-types/:id
  Soft delete (sets deleted_at, deleted_by)
  Checks: not used in customers/suppliers

=== PERMISSIONS ===

beneficiary_types.read (GET endpoints)
beneficiary_types.create (POST)
beneficiary_types.update (PUT)
beneficiary_types.delete (DELETE)

=== KEY PATTERNS ===

1. Soft Delete
   - Delete sets deleted_at = NOW()
   - SELECT always filters WHERE deleted_at IS NULL

2. Audit Trail
   - created_by, updated_by, deleted_by track users
   - created_at, updated_at, deleted_at track changes

3. Modal Forms
   - Single modal component for add/edit/delete
   - Reusable across different tables

4. Parent-Child Events
   - Child emits: 'beneficiary-type-saved', 'beneficiary-type-deleted'
   - Parent reloads list on event

5. Error Handling
   - Frontend: SweetAlert2 notifications
   - Backend: sendErrorResponse() with HTTP codes
